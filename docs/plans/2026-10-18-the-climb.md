# The Climb, piece 1 (the core loop): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A playable one-act roguelike run: bring five owned players, pick a playbook and a boon at Training Camp, climb a seeded 7-floor map of one-quarter games against the coach, take strat and player rewards, rest or practice, and bank a server-computed pot.

**Architecture:** The run is a pure, seeded state machine (`src/game/modes/run.js`) over a server-shareable map and pot module (`climbMap.js`). Games are ordinary engine games started at Q4 section 1 with carried fatigue, upgraded copies riding in the deck as `id+`, handed to the Play tab as a fixture-style preset. The server keeps a ledger per run: it rebuilds the map from the run's seed, so it knows each stop's kind and floor without trusting the browser, and it alone pays the pot.

**Tech Stack:** React 18 + Vite, Vitest, Firebase (Firestore, Cloud Functions v2 callables), the existing engine (`src/game/engine.js`, `execCard.js`, `canPlay.js`, `ai.js`, `modes/simulate.js`).

**Spec:** `docs/plans/2026-10-18-the-climb-design.md`

## Global Constraints

- Starting values, all tuned by Task 10's simulated runs before the user plays: starting run cap **$2,200**; cap **+$300 per floor cleared**; Game opponent cap **$2,600 at floor 1 to $4,000 at floor 7**; Rivalry **+$700**; boss cap **median team salary at the boss x 1.2 to 1.4** (start: **$5,200**); coach deck **15 cards at floor 1, 25 for the boss**; rare chance **5% at floor 1 to 25% at floor 7**; pot **Game 30 to 60 coins by floor, Rivalry 70, Boss 120 + a Booster, all x the rung's pay factor**.
- One act, 7 floors + boss, 3 lanes; floor 1 all Games; floor 7 all Rest Days; every path has at least one Rivalry and one Rest Day on floors 2-6; no path has two Rest Days in a row (so floor 6 is never a Rest Day).
- A run game is one quarter: Q4 section 1 onward, crunch and overtime as the engine already does them. `CRUNCH_MARGIN`, the fatigue ladder and the rest rule are not changed.
- One loss ends the run and forfeits the pot. Retire only between stops. A game that started and never reported counts as a loss. A pot banks once.
- Run games pay nothing per game; no daily first-win, milestone or Bam coins come from them. Lifetime card stats record for owned players only.
- **Strategy card approval rule:** the kits and every "+" text are approved by the user (Task 1) before Task 6 ships them.
- The repo is public: no app user's name or email in code, docs or commits.
- UI conventions: no native dialogs (`ask()`/`toast()`); every card image on a menu opens the whole card (`ZoomImg`, CardLightbox.jsx); one 768px breakpoint; `motion.css` tokens.
- Do not re-export card PNGs for this work.
- Deploy order: `firebase deploy --only firestore:rules`, then `firebase deploy --only functions`, then `npm run deploy`. `main` is fast-forwarded only after the user confirms the deploy.

## Decisions this plan makes (the spec left them open or the code overruled it)

1. **The kits are hand-drafted, not derived.** The spec derived each playbook's eight signature cards from the cards its fitted fifty (archetypeDecks.js) uses more than the other two. Measured: the three fifties differ by at most one copy per card (fast has 4 such cards, big 1, stoppy 1), so the rule yields nothing. Task 1 drafts them from what each card asks for, for the user's approval with the "+" batch.
2. **Fatigue between games: a set recovery, more for a bigger win** (the user, 2026-10-18). Every player's end-of-game tracker comes down 8 minutes, 10 after a win by 10+, 12 after a win by 20+ (`CLIMB.recovery`, starting values). Why it is needed: a five-man roster has no bench and a quarter is 12 minutes, so with no recovery a starter opens game 3 at 24 minutes (-24 a roll). With 8, close wins open a starter's games 1-4 at 0 / 4 / 8 / 12 minutes. A recovery off the tracker, rather than a flat "wear" per game, keeps the in-game choice alive: a tired player you sit for a section rests on the bench and carries less.
3. **Opponent rosters are sized like the run's own** so the cap compares like for like: 5 players at floors 1-2, 6 at 3-4, 7 at 5-6, boss 8 (starting values; buildAiRoster is ten-deep today, and $2,600 over ten players is a team of minimum salaries).
4. **An upgrade is one copy** (the user, 2026-10-18). An upgraded copy is the id with a `+` (`'close_out+'`) in the deck, hand and discard, so it travels as itself through every draw, discard and undo. The engine compares ids as strings in ~40 places, so the `+` is read at the doors, never inside: `execCard` and `canPlay` take the base id and a `plus` flag, the hand removal uses the copy's own id, id lists (`CRUNCH_CARDS`, `TIMEOUT_RIDERS`, answer cards) and the AI's per-card tables look up `baseId(id)`, and the image helpers draw the base face. A `+` id only exists in a Climb deck, so a normal game cannot meet one. Task 3's guard test plays simulated games with every copy upgraded.
5. **The map is rebuilt from a server-chosen seed.** `climbStart` picks the seed; the browser and the server run the same `generateMap(seed)`, so the server prices each stop itself.
6. **The boss's Booster arrives as a one-pack box** (`users/{uid}/boxes`, `left: 1`, `boughtAs: 'climb'`), opened by the existing `openBoxPack` from the Collection tab's unopened boxes.
7. **A tie after the last overtime is a loss** (it is not a win, and the claim's `won` is false).
8. **Rewards offer no legendary strats in piece 1;** the rare slot draws `rarity: 'rare'`.
9. **Entry point:** a `climb` route, not a new nav tab. It lights the Play button while open (as `season` lights Dynasty) and is opened from a "The Climb" button on the Play tab's start screen and from the Home NEWS item.

## Review Focus

- **Resuming a run game on reload or another device:** the run must hand the Play tab the same preset key and the same stored opponent, so the saved game resumes instead of a fresh deal. Pinned in Task 5 (`gameSetup` is stored on the run and reused).
- **A saved run holding a card key that no longer resolves** (renamed, aliased, removed from the pool): aliases are followed; an unknown key is dropped; a roster that falls under five blocks play and offers Retire. Pinned in Task 5.
- **A tie after the last overtime:** the run ends lost, the server agrees. Pinned in Tasks 5 and 7.
- **Nothing fits under the cap, or the roster is already ten:** no player offer, no empty picker. Pinned in Task 5.
- **A late or stale claim** (a stop that is not the open one, a run already lost or banked): pays nothing, changes nothing, answers with the run's status. Pinned in Task 7.
